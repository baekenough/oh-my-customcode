# R008: Tool Identification Rules

Every tool call MUST be prefixed with agent and model identification so every action is traceable.

## Overview

Tool identification pairs with [[r007]] (agent identification) to create full traceability. Users see not just which agent is active but precisely which tool it is calling and on what target. The `[N]` prefix system for parallel spawns enables correlation with the Running display in Claude Code.

## Priority

**MUST** — Enforced. Missing identification prefix on tool calls requires immediate correction. PostCompact hook re-injects this rule.

## Key Requirements

**Format:**
```
[agent-name][model] → Tool: <tool-name>
[agent-name][model] → Target: <file/path/url>
```

**Model shorthand:** `opus`, `sonnet` (default), `haiku`

**Tool category verbs:**

| Category | Tools | Verb |
|----------|-------|------|
| File Read | Read, Glob, Grep | Reading / Searching |
| File Write | Write, Edit | Writing / Editing |
| Network | WebFetch | Fetching |
| Execution | Bash, Agent | Running / Spawning |

**Parallel spawn prefix rule:** When spawning 2+ agents, each Agent tool's `description` parameter MUST include a `[N]` 1-indexed prefix for Running display correlation:
```
Agent(description: "[1] Go code review", subagent_type: "lang-golang-expert")
Agent(description: "[2] Python code review", subagent_type: "lang-python-expert")
```

Single agent spawns do NOT use the `[N]` prefix.

**Single spawns still need the Core Rule prefix (#1652 #3-3, advisor parity #1650 E):** a single Agent spawn does not use the `[N]` item form — instead it must print the Core Rule prefix line (agent/model brackets + arrow + Tool label + `Agent`) immediately before the call. The advisor (`.claude/hooks/scripts/r007-r008-drift-advisor.sh`) now counts **four** things as an announce: a Tool-label line, a bracketed-number spawn item, a **bare single-spawn line** (agent-type:model followed directly by an arrow and description, no bracketed number — added in #1650 E), and the Spawning header line — and among the three spawn-representation forms exactly one is selected per the priority **bracketed item > bare line > Spawning header**. The prior miscount, where a response using only the bare-line form was logged as an R008 miss, was resolved in **v1.1.62** (measured v1.1.60 → reproduced via the v1.1.61 adversarial review → fixed by the #1650 E change). **The format the rule still requires is the Core Rule prefix line** — counting the bare line closes a false-positive gap, it does not promote the bare line to the required format. When a prefix line and a bare line are both present, the advisor treats the bare line as a companion line (same as a Target line) and **subtracts** it, so pairing them does not double-count. If applied further, this clause's advisor-behavior description must be updated in the same commit ([[r016]] Rule Wiring Check).

### Spawn Announce literal — advisor-regex parity (#1595 #5)

The spawn-announcement examples above match `.claude/hooks/scripts/r007-r008-drift-advisor.sh`'s verdict formula **literally**. The following variants do **not** match, so a rule-compliant response gets counted as an R008 violation:

| Forbidden variant | Why it fails to match |
|-------------------|-----------------------|
| A list marker or backtick before the number | The spawn-item regex requires the **bracketed number at the start of the line** and allows only leading whitespace |
| The Spawning header written without its colon (e.g. "Spawning 4 agents") | The header regex requires the **colon** |
| Agent-type/model followed by a description with no arrow | The spawn-item regex requires an **arrow** — only U+2192, the ASCII hyphen-greater pair, and the U+2014-greater pair are recognized |

When rule wording and detector regex diverge, the resulting false count becomes the argument for amending the rule again. Change the advisor regex in the same commit as any format change ([[r016]] Rule Wiring Check).

**Authoring caution:** the advisor's announce regex has **no line-start anchor**, so embedding a complete literal inside a table cell or inline backticks makes any turn that quotes this document **count as an announce** (measured across 482 turns). Keep format examples inside code fences at line start, and describe them in prose within tables.

Cross-ref: [[r009]] 「Narrative announcement format」 (same literal applied to prose announcements), [[r020]] 「자가 계수는 advisor 판정식을 재현한다」.

Origin: #1595 #5 (v1.1.48 session — three R008 violations concentrated in one turn, computed as tool_use=5 / announce=2. The actual announces were prefixed with list markers and backticks so none matched, and the header lacked its colon).

> **v2.1.174+**: Fixed the Workflow tool's `agent()` subagents missing per-agent attribution headers. Workflow-spawned subagents now carry attribution consistent with R008. When authoring Workflow scripts, treat each `agent()` call with the same per-agent identification model as parallel Agent tool spawns — `[agent][model] → Tool:` discipline applies to Workflow fan-outs too.

## Required-Parameter Completeness Check (#1324)

Announcing the prefix and invoking the tool are separate steps — a prefix alone does not guarantee the call payload is complete. Before invoking, confirm required schema parameters are filled, not just that the prefix line was printed:

| Anti-pattern | Required |
|--------------|----------|
| A Core Rule prefix line (agent/model brackets, then the arrow and the Tool label) printed before an AskUserQuestion call that is then invoked with an empty/missing `questions` array | Prefix + a non-empty `questions` array in the same call |
| Required fields omitted after the announce (announce-payload separation gap) | Complete the required fields in the same message as the announce |

Cross-references [[r020]] (action-completeness precondition — verify required parameters before invoking).

## Tier-3 Interaction Tool Prefix (MANDATORY)

"Every tool call" is not limited to file/exec tools — interaction tools need the same prefix:

| Tool | R008 prefix required? |
|------|----------------------|
| AskUserQuestion | YES |
| TodoWrite | YES |
| EnterPlanMode / ExitPlanMode | YES |
| Skill | NO — identified via the [[r007]] integrated `claude → {skill-name}` header instead |

The Core Rule prefix form (agent/model brackets + arrow + Tool label) applies to Agent/Bash/Read **and** to the interaction tools above; applying it only to the former is a violation.

Skill invocation is the sole exception, since it already carries identification through R007's header.

## Multi-Turn Self-Check (MANDATORY)

Before every tool call, re-check rather than trusting that the prior call carried a prefix:
1. Does a Core Rule prefix line (agent-name/model brackets + arrow + Tool label + tool name) precede this call?
2. Do agent-name and model match the current context?
3. Are all schema-required parameters filled (not just the prefix printed)?

Fix the prefix/parameters immediately if the check fails.

## Short Response Discipline (v0.147.0)

도구 호출 prefix도 응답 길이와 무관하게 필수. 같은 턴 내 여러 도구를 호출할 때 각 호출 직전에 개별 prefix 표시:

```
[agent][model] → Tool: Read
[agent][model] → Target: file1.md
<Read call>

[agent][model] → Tool: Bash
[agent][model] → Target: gh issue list
<Bash call>
```

Reference issues: #1188 item #3, #1198 item #3.

## External-Project / Debugging Session Vigilance (#1401, #1417)

R007 헤더와 마찬가지로, R008 prefix 누락도 외부 프로젝트 디버깅·배포 세션에서 가장 자주 발생한다. R007/R008은 세트로 함께 자가 점검한다.

| 세션 유형 | R008 prefix |
|-----------|-------------|
| oh-my-customcode 작업 | 필수 |
| 외부 프로젝트 디버깅 | **동일하게 필수** |
| SSH / 배포 / 인프라 작업 | **동일하게 필수** |

외부 프로젝트 진단 세션(#1417)에서 Bash/Edit/Read/Agent 모든 호출에 `[agent][model] → Tool:` prefix가 세션 전체 누락된 재발이 관측되었다 — 도구 호출 직전 prefix 부착을 워크플로에 내재화한다.

Reference issues: #1401, #1417.
