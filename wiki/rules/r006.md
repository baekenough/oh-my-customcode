# R006: Agent Design Rules

Defines the file format, required frontmatter, optional fields, naming conventions, and separation-of-concerns architecture for all agents and skills.

## Overview

Agents live in `.claude/agents/{name}.md`. Skills live in `.claude/skills/{name}/SKILL.md`. Guides in `guides/`. These three locations have distinct purposes and must not be conflated. The agent frontmatter defines identity, tools, model, and behavior. The body describes role and workflow — not detailed instructions (those belong in skills).

## Priority

**MUST** — Agent files with invalid frontmatter or wrong structure cause routing failures and R017 verification failures.

## Key Requirements

**Required frontmatter fields:** `name`, `description`, `model`, `tools`

**Model specification is 3-tier — the correct value for the SAME string depends on WHERE it is placed:**

| Tier | Where valid | Values | Notes |
|------|-------------|--------|-------|
| **1. CC native alias** | Frontmatter `model:` AND Agent tool `model` param | `sonnet` \| `opus` \| `haiku` \| `opusplan` \| `inherit` | Resolved by CC itself, not by project docs — e.g. `model: sonnet` currently resolves to `claude-sonnet-5` (CC default, v2.1.197+); the project cannot pin this by documentation alone |
| **2. Full model ID** | Frontmatter `model:` ONLY (recommended) | `claude-sonnet-5` \| `claude-opus-5` \| `claude-haiku-4-5` \| `claude-opus-4-6` \| `claude-opus-4-8` \| `claude-fable-5` (+ optional `[1m]` suffix) | Explicit — does not silently drift when the platform default changes. All 49 project agents use this form: `claude-sonnet-5` ×41, `claude-opus-5` ×5, `haiku` ×3 |
| **3. Agent tool `model` param (enum)** | Agent tool call ONLY | `sonnet` \| `opus` \| `haiku` \| `fable` — **exactly these 4** | Does NOT accept full model IDs. Routing-skill spawn instructions (`Agent(model: opus)`) MUST use this enum form |

> **Deprecated/virtual alias names — do not use**: `sonnet5`, `opus5`, `opus48` (frontmatter shorthand) are aliases this project previously documented in R006 but **CC does not interpret these strings** — a spawn using them fails immediately (confirmed on CC v2.1.220). Use Tier 2 full IDs (`claude-sonnet-5`, `claude-opus-5`, `claude-opus-4-8`) in frontmatter instead. Note `fable` itself remains valid — but only as the Tier 3 Agent-tool enum value; as a frontmatter shorthand for `claude-fable-5` it is Tier 2 full-ID usage, not a Tier-1/3 alias.
>
> Origin: this correction stems from a same-session incident (2026-07-29) where a Tier-3 spawn using `opus5` failed — the string is valid nowhere in the enum CC actually accepts for that parameter position.

> `claude-opus-5` is CC's default Opus model (v2.1.219+) — native 1M context. `claude-opus-4-8` is now a **previous-generation** Opus model (superseded by Opus 5) — do not describe it as the latest Opus. **The Tier-1 base `opus` alias is resolved by CC itself, not by project documentation — the project cannot pin it to a specific version.** Agents that need a version-stable Opus MUST use the Tier-2 full model ID (`claude-opus-5`, `claude-opus-4-8`, etc.) in frontmatter instead of the bare `opus` alias. **The relative capability tier of Opus 5 vs. Fable 5 is not confirmed from official sources — do not assert an ordering between them.**

> **v2.1.222+ org-restricted family alias step-down:** in **org-restricted environments**, a `model: opus`-family subagent/teammate alias that was falling back to the parent model now correctly steps down to the org-allowed **latest model within that family** instead. This is a case that strengthens the Tier 1 principle above ("CC resolves these, not this project") — Tier-1 alias resolution now has an additional org-restriction variable the project cannot pin, so specific-model guarantees still require the Tier-2 full ID in frontmatter. The Agent tool spawn parameter (Tier 3) does not accept full IDs, so alias resolution on that path remains subject to org settings. (This repo's own org-restriction status is unmeasured — the condition above is the applicability scope.)

> **v2.1.223+ restricted-model step-down is now WARNED, not silent:** when a workflow agent, forked skill, slash command, or resumed background agent requests a subagent model that is restricted and therefore runs as the parent model instead, CC now displays a warning. This is the direct continuation of the v2.1.222 org step-down note above, and its significance is evidentiary: **before this fix the step-down was silent**, so "the spawn said `model: opus`" was never evidence of the model that actually executed. Pin with a Tier-2 full ID in frontmatter, and read the warning (or its absence) to confirm the executing model — the model-selection angle of [[r020]] "attempt ≠ outcome".

> **v2.1.223+ `CLAUDE_CODE_DISABLE_1M_CONTEXT` widened to all 1M models:** the env var now keeps **every** Claude model with a native 1M window pinned to 200K via auto-compaction (previously a fixed model list), and unrecognized model IDs are also held within an assumed context window (restore with `CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1`). Consequence for the Tier-2 table above: `claude-sonnet-5` / `claude-opus-5` and the `[1m]` suffix operate at an **effective 200K** wherever this env is set, so verify the env before delegating work that assumes a 1M budget (cross-ref [[r013]] context budget).

> **Frontmatter `tools:` typo detection (v2.1.208+):** The Agent tool no longer silently launches with no tools when a subagent's `tools:` list resolves to nothing — it now returns a clear error naming the unrecognized entries. Catches `tools:` typos in agent frontmatter that previously failed silently at spawn time.

> **Claude Sonnet 5 = CC 기본 모델 (v2.1.197+)** — Claude Sonnet 5가 Claude Code의 **기본 모델**로 도입되었습니다. 네이티브 1M-token 컨텍스트, 프로모션 가격 $2/$10 per Mtok(2026-08-31까지). frontmatter에서는 `model: claude-sonnet-5`(Tier 2, 명시 opt-in)로 사용한다 — `sonnet5`는 CC가 해석하지 않는 폐기된 표기이므로 사용 금지(위 Deprecated/virtual alias 참조). **정정(실측)**: Tier-1 base `sonnet` alias는 CC가 해석하며 프로젝트가 특정 버전에 고정할 수 없다 — frontmatter `model: sonnet` 에이전트는 실측상 `claude-sonnet-5`로 실행된다. 버전 고정이 필요하면 bare alias 대신 Tier 2 full model ID(`claude-sonnet-5`)를 명시한다. Sonnet 5가 CC 신규 기본값이므로 명시 모델 없는 세션은 이제 Sonnet 5에서 동작한다.

> **Fable 5 Effort 전략 (Origin: #1435)** — Fable 5는 **high effort가 기본값**이며, `xhigh`는 capability-sensitive 작업(최고난도 아키텍처/추론)에 한정해야 한다. Fable 5의 `low`/`medium` effort조차 이전 세대 모델의 `xhigh`를 상회하는 품질을 보이므로, Fable 5 실행 에이전트는 `effort` 필드를 신중히 명시하고 불필요한 `xhigh` 남용을 지양한다(R005 비용/지연 인식과 정합).

> **Mythos 5 (`claude-mythos-5`)** — Project Glasswing 한정 공급 모델로 **GA가 아니다** — Fable 5(GA, 위 `fable` alias)와 구분해야 한다. adaptive-thinking 전용 아키텍처 + 안전 분류기 개입 시 `stop_reason: "refusal"` fallback 체계를 가진다. oh-my-customcode 에이전트 frontmatter에는 아직 alias 미등록(비-GA, 공급 제한).

> **프롬프팅 패턴 상호참조** — Fable 5/Mythos 5 대상 프롬프팅 패턴(effort 조합, adaptive-thinking 활용, refusal fallback 대응)의 상세 가이드는 `guides/claude-code/16-fable5-prompting.md` 참조.

**Separation of concerns:**

| Location | Purpose | Contains |
|----------|---------|----------|
| `.claude/agents/` | WHAT the agent does | Role, capabilities, workflow |
| `.claude/skills/` | HOW to do tasks | Instructions, scripts, rules |
| `guides/` | Reference docs | Best practices, tutorials |

**Skill scope:**

| Scope | Deployed via init? |
|-------|--------------------|
| `core` | Yes |
| `harness` | Yes |
| `package` | No |

`context: fork` is reserved for multi-agent orchestration skills only (routing skills, DAG orchestration, task decomposition) — capped at **12 total** project-wide (currently 10/12: secretary/dev-lead/de-lead/qa-lead-routing, dag-orchestration, task-decomposition, worker-reviewer-pipeline, deep-plan, professor-triage, roundtable-debate). Best-practices, hook/command, and single-agent-reference skills must NOT use `context: fork`.

**Protected paths:** `.claude/agents/*.md`, `.claude/skills/*/SKILL.md`, `guides/*/` (new dirs) — creation MUST go through `mgr-creator` per [[r010]].

## Artifact Output Convention

Skills persist output to `.claude/outputs/sessions/{YYYY-MM-DD}/{skill-name}-{HHmmss}.md`. Opt-in, git-untracked. Final subagent writes per [[r010]].

## Sensitive Path Handling

> **Status (CC v2.1.121+):** Direct Write/Edit/Bash on `.claude/`, `.git/`, `.vscode/` works without prompts under `mode: "bypassPermissions"`. The historical `/tmp/*.sh` bypass pattern is deprecated. See #1101.

Under `bypassPermissions`, all `.claude/**` paths (including `.claude/outputs/**`, `.claude/agents/**`, `.claude/skills/**`, `.claude/rules/**`, `templates/.claude/**`) accept Write/Edit/Bash directly. Catastrophic shell operations remain blocked by independent safety guards.

**Recommended practice:**
1. Pass `mode: "bypassPermissions"` on every Agent tool call (R010 Universal bypassPermissions)
2. Use Write/Edit directly for `.claude/**` paths — no `/tmp/*.sh` wrapping needed
3. For CC < v2.1.121: the legacy `/tmp/*.sh` bypass pattern applied — see git history

Note: `.claude/**` glob does not cover `templates/.claude/**` — separate allow rules still required in non-bypassPermissions modes.

## CC Platform Settings (v2.1.166+–v2.1.169+)

**Fallback models (v2.1.166+):** `fallbackModel` in settings configures up to three fallback models tried in order when the primary is overloaded or unavailable. Complements the per-agent `model:` field; handled at the platform level rather than per-agent frontmatter.

**Thinking toggle (v2.1.166+):** `MAX_THINKING_TOKENS=0`, `--thinking disabled`, or the per-model toggle disables thinking on models that think by default. Useful when an agent's `effort` is low and thinking overhead is undesirable.

**VS Code transcript bug (v2.1.170 fix):** Sessions started from the VS Code integrated terminal no longer fail to save the session transcript (and transcripts now appear in `--resume`). Skills that depend on episodic memory or transcript replay (e.g., `homework`, `episodic-memory`) are affected when this bug is present — upgrade to CC v2.1.170+ to ensure transcripts are saved in VS Code terminal sessions.

**Safe Mode (v2.1.169+):** `--safe-mode` (env: `CLAUDE_CODE_SAFE_MODE`) starts CC with ALL customizations disabled — CLAUDE.md, plugins, skills, hooks, MCP servers. Use it to isolate whether a project agent/skill/hook causes a regression.

**Bundled skill control (v2.1.169+):** `disableBundledSkills` setting (env: `CLAUDE_CODE_DISABLE_BUNDLED_SKILLS`) hides CC's bundled skills, workflows, and built-in slash commands from the model. Useful when bundled skills conflict with or duplicate project skills. Distinct from the advisory `skills:` frontmatter field, which is documentation metadata and not a runtime allowlist — see the `skills:` note in the source rule.

**`availableModels` subagent overrides (v2.1.172+):** `availableModels` restrictions now apply to subagent `model:` overrides, the agent dispatch model picker, and the advisor model. Allowlists using version-specific IDs (e.g. `claude-opus-4-8`) no longer hide the Opus/Sonnet 1M picker rows, and model IDs no longer receive a doubled 1M suffix (`[1M][1m]`) when `ANTHROPIC_DEFAULT_OPUS_MODEL` already includes one. Relevant when restricting per-agent model overrides via `availableModels`.

**Fable 5 `[1m]` auto-normalization (v2.1.173+):** Fable 5 model IDs carrying a `[1m]` suffix are auto-normalized (suffix stripped) because Fable 5 includes 1M context by default. Use `claude-fable-5` / `model: fable` WITHOUT a `[1m]` suffix — appending it is redundant. The `[1m]` suffix remains meaningful for Opus/Sonnet IDs.

**`enforceAvailableModels` managed setting (v2.1.175+):** When enabled, the `availableModels` allowlist also constrains the **Default** model — a Default that would resolve to a disallowed model falls back to the first allowed model, and user or project settings can no longer widen a managed `availableModels` list. Extends the v2.1.172 `availableModels` scope (subagent `model:` overrides, dispatch picker, advisor model) to the Default model itself. Relevant in enterprise/managed configs that pin the allowed model set: both per-agent `model:` overrides AND the resolved Default honor the allowlist.

- **Hook `if:`/allow-rule scope narrowing (v2.1.214+):** A single-segment `dir/**` hook `if:` condition or `allow` permission rule now matches only `<cwd>/dir` rather than any depth in the tree (use `**/dir/**` for any-depth matching). `deny`/`ask` rules retain any-depth matching — this asymmetry (narrow allow, broad deny/ask) should be assumed when designing `settings.json` scope rules.

## Hook System

Agents (and skills, via the same `hooks:` frontmatter syntax) can register handlers for **31 event types** — `SessionStart`, `Setup`, `UserPromptSubmit`, `UserPromptExpansion`, `PreToolUse`, `PermissionRequest`, `PermissionDenied`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `Notification`, `MessageDisplay`, `SubagentStart`, `SubagentStop`, `TaskCreated`, `TaskCompleted`, `Stop`, `StopFailure`, `TeammateIdle`, `InstructionsLoaded`, `ConfigChange`, `CwdChanged`, `DirectoryAdded` (v2.1.219+, fires after `/add-dir` or SDK `register_repo_root`), `FileChanged`, `WorktreeCreate`, `WorktreeRemove`, `PreCompact`, `PostCompact`, `Elicitation`, `ElicitationResult`, `SessionEnd` — dispatched to one of **4 handler types**:

> **Correction (2026-07-30 resync):** the event previously documented here as `PostMessage` is not a real event name — the actual event is **`MessageDisplay`**, and it is **display-only**: `hookSpecificOutput.displayContent` replaces only the on-screen text, while the transcript and what Claude itself sees remain the original content. An advisory hook wired to `MessageDisplay` therefore **never reaches the model**. Events that DO support `additionalContext` (model-context injection): `SessionStart`, `Setup`, `SubagentStart`, `UserPromptSubmit`, `UserPromptExpansion`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `Stop`, `SubagentStop`.

| Handler | Behavior |
|---------|----------|
| `command` | Execute shell command, stdin receives JSON context |
| `prompt` | Inject text into model context |
| `http` | POST to HTTP endpoint |
| `agent` | Spawn agent to handle event |

`PreToolUse` supports a `{"decision": "defer"}` return (v2.1.89+) to pause headless sessions at a tool call for human review. `PreCompact` supports `exit 2` / `{"decision": "block"}` (v2.1.105+) to prevent context compaction mid-workflow. Agent frontmatter `hooks:` fire both when spawned as a subagent AND (since v2.1.116+) when run as a main-thread agent via `--agent`. This project's own `.claude/hooks/` mechanism ([[r021]] Enforcement Tiers) is built on this same event system.

## Fast Mode

Fast Mode (`/fast` toggle or `fastMode` setting) runs the **same model** with faster, less-deep output — it does NOT switch to a cheaper model:

| Aspect | Normal | Fast Mode |
|--------|--------|-----------|
| Model | As configured | Same model |
| Output speed | Standard | ~2.5x faster |
| Reasoning depth | Full | Reduced |

Independent of the agent frontmatter `effort` field — `effort` controls task-complexity allocation, Fast Mode controls output-generation speed.
