# R013: Ecomode Rules

Defines automatic token efficiency mode for batch, parallel, and high-context operations — compressing both output and input context.

## Overview

Ecomode activates automatically when 4+ parallel tasks are running, batch operations are detected, context usage exceeds 80% (or lower task-type-specific thresholds), or the user explicitly enables it. Both output compression and input context pruning are active under ecomode.

## Priority

**SHOULD** — Strong recommendation. Ecomode prevents context overflow and reduces token costs in large operations. Override with "ecomode off" or "verbose mode".

## Key Requirements

**Auto-activation triggers:**
- 4+ parallel tasks
- Batch operations
- Context usage > threshold (task-type-specific)
- Explicit "ecomode on"

**Task-type context thresholds:**

| Task Type | Trigger |
|-----------|---------|
| Research | 40% |
| Implementation | 50% |
| Review | 60% |
| Management | 70% |
| General | 80% |

**These thresholds are percentages of the window, not absolute token counts (v2.1.223+):** `CLAUDE_CODE_DISABLE_1M_CONTEXT` now holds **every** Claude model with a native 1M window at 200K via auto-compaction (previously only a fixed model list), and unrecognized model IDs are likewise kept inside an assumed window (`CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1` restores the old behavior). The same "Research 40%" therefore means 400K tokens on a live 1M window but 80K where this env is set — a 5x swing. Check the env before budgeting on a 1M assumption (cross-ref [[r006]] model tiers).

**Unbounded memory growth fixed (v2.1.238+):** long-lived interactive sessions no longer retain subagent tool results past the visible display window — previously these could accumulate without bound (including autonomous loops like `/fsd`), skewing context/memory budget math. Task-type threshold calculations from before this fix may have been inaccurate on long sessions retrospectively.

**Sonnet 5's full-1M auto-compact window (v2.1.251+):** the default auto-compact trigger for Sonnet 5 changed to the entire 1M context — 1M-window sessions now auto-compact around ~967K tokens instead of ~934K. This directly interacts with the `CLAUDE_CODE_DISABLE_1M_CONTEXT` note above: where that env is **set**, the 200K cap still holds; where it's **unset** (default), this change raises the effective auto-compact threshold itself. Since most agents in this repo run `claude-sonnet-5`, accurate absolute-token budgeting now requires checking both the env setting and this CC version.

**Aggregation format:**
```
[Batch Complete] {n}/{total}
├── {agent}: ✓/✗/⚠ {summary}
```

**Input context pruning strategies:**

| Strategy | When |
|----------|------|
| Retain | Directly relevant code/docs |
| Summarize | Background context, prior hop results |
| Drop | Search noise, duplicates, already-reflected info |

Track pruning: `[Pruned] {N} chunks → {M} retained, {K} summarized, {J} dropped`

## Enforcement

Prompt-based + `context-budget-advisor.sh` hook (advisory warnings) per [[r021]].
