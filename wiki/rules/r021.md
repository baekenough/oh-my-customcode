# R021: Enforcement Policy

oh-my-customcode uses an advisory-first enforcement model. Most rules are enforced through prompt engineering rather than hard-blocking hooks, preserving agent flexibility while maintaining behavioral standards.

## Overview

Hard-blocking hooks are reserved for critical safety boundaries. The majority of MUST rules are enforced through PostToolUse advisory hooks, post-compaction rule re-injection, and CLAUDE.md prompt guidance. This prevents agents from getting trapped in unrecoverable states while still maintaining standards.

**Correction (#1619 #7, 2026-08-29):** the documented-guaranteed re-injection path after `/compact` is the **`SessionStart`** hook (matcher `*`, `claude-md-reinject.sh`, v1.1.50 #1617) — NOT the `PostCompact` event. The historical `PostCompact` prompt wiring is still in place, but the official docs do not define an `additionalContext` field for `PostCompact`, so its actual effect is unconfirmed and its firing is unmeasured. The first report of this (during a hook-events audit) claimed `PostCompact` did not exist at all; re-measurement corrected that to "exists, but `additionalContext` is undefined for it" — an unverified sub-agent citation propagating a wrong premise into a retrospective issue, corrected only by direct measurement ([[r020]] cause-diagnosis-is-also-a-hypothesis clause in action).

**Follow-up binary probe (2026-08-29, CC 2.1.251):** a dedicated `postcompact-probe` confirmed the `PostCompact` dispatch path itself is real — a dedicated execution function, a payload schema of `trigger`/`compact_summary`, and dispatch-map registration, structurally isomorphic to `PreCompact`. This narrows "firing unmeasured" to **"dispatch path is real; live firing and the prompt-handler's effect remain unmeasured"** — the `additionalContext` field is still undefined, so the guaranteed re-injection path remains `SessionStart`, unchanged by this finding.

## Priority

**MUST** — The enforcement policy itself defines how all other rules are enforced.

**Advisory (proactive/retroactive) firing defect and resolution (measured):** the `hookSpecificOutput.additionalContext` delivery path itself was correctly implemented in #1547 (v1.1.40) — but a **parser selector defect upstream of it** meant the advisory **never fired through v1.1.42**. Both scripts read `jq -r '.role'`, but transcripts have no top-level `role` key (the real path is `.message.role`), so `last_assistant` was always empty and the script exited 0 silently before emitting anything. Measured at the time: 0 occurrences of `"additionalContext":` across 771 transcripts, and a live probe emitted 0 bytes on both stdout and stderr. **Both the proactive layer (`r007-r008-drift-advisor.sh`) and the retroactive layer (`session-reflection.sh`, same defect) were silent.** **v1.1.43 fixed the parser on both layers and added the `PostToolUse` wiring — a live probe confirmed the first actual firing (#1553).** Follow-ups: v1.1.44 switched the R008 verdict from block-adjacency comparison to turn-level prefix counting (#1563), and v1.1.45 added a Skill-tool exemption (#1569).

**v1.1.49 added the reverse signal (#1595 #6)** — the direction where tool calls are announced but the turn ends with no `tool_use` block at all. The existing verdict formula (tool_use minus announce, floored at 0) treats that direction as **structurally zero**, so it was undetectable in principle. The reverse leg uses its **own anchored regex** (line-start anchor present — deliberately NOT applied to the forward leg, where under-counting announces would *increase* reported violations) and fires only when **every** `tool_use` block including Skill is 0 (using the Skill-excluded count would misfire on compliant Skill-only turns). It ships **default off**, enabled with `OMCUSTOM_R008_REVERSE=on`: across a 482-turn measurement, the naive "announce − ntools > 0" implementation fired on 36 turns and doubled total advisory volume (16 were Skill-exclusion artifacts, 15 were prose matches from the unanchored regex); after narrowing it reached 3/3 true positives with 0 false positives (the anchor cost 1 line out of 969 real announce lines, 0.1%), but a 3-item sample was too small to enable by default. **The wiring also gives it no preventive effect**, a second reason for holding it off: the defective turn has 0 `tool_use`, so `PostToolUse`/`SubagentStop` never fire, and `UserPromptSubmit` fires only after the user has already intervened. The one event that fires on time is `Stop`, whose hook is `session-reflection.sh` — so the reverse signal is **deliberately advisor-only** and was not replicated there (duplicating the report would still yield zero correction opportunities while doubling the places to revert).

Lesson: **wiring confirmed ≠ delivery confirmed ≠ firing confirmed** — the [[r020]] "actual outcome ≠ attempt" principle reproduced in the hook domain.

**CC v2.1.163+:** Stop and SubagentStop hooks can return `hookSpecificOutput.additionalContext` (JSON) to feed structured feedback back into Claude's context without triggering a hook error label — enables advisory-style enforcement via Stop/SubagentStop hooks to pass richer context without disrupting turn continuation.

**CC v2.1.199+:** Fixed SessionStart/Setup/SubagentStart hooks silently swallowing stderr when exiting with code 2 — errors are now surfaced. Strengthens observability for the Hard Block/Advisory tiers in the table above (cf. the v2.1.163 `additionalContext` structured feedback note).

**CC v2.1.210+ (retired v1.1.45):** Fixed hook callback timeouts being misreported to the model as a user rejection, which had caused unattended sessions to stall waiting on a phantom denial. Since R021 advisory hooks fire every turn and long-running unattended loops (e.g. `/fsd`) depend on them, a hook timeout no longer aborts an unattended session. Retired to an HTML comment in the source at v1.1.45 under the [[r016]] v2.1.212 retention floor — the v2.1.211/212/214 note below carries the still-visible enforcement-reliability chain.

**CC v2.1.211/212/214+:** Three platform fixes make hook enforcement decisions reliable in auto/unattended mode: (211) auto mode no longer overrides a PreToolUse hook's `ask` decision on unsandboxed Bash — the `ask` now floors to at least a minimal prompt; (212) `continue:false` hook halts are no longer dropped on tool failure or mid-completion, and hook infrastructure errors are no longer misreported as user rejections; (214) `exit 2` now reliably blocks even when hook stdout JSON fails schema validation. All three strengthen the Hard Block and Conversation Block tiers above (`stage-blocker`, `rule-deletion-guard`, `stuck-detector`), extending the v2.1.210 phantom-rejection fix.

**CC v2.1.222+:** fixed a PreToolUse auto-allow hook bypassing tool restrictions on background agent tasks (summaries/compaction/renames) — meaning the Hard Block tier above (`stage-blocker`, `dev-server tmux`, `rule-deletion-guard`) could previously be bypassed on that background-agent task path, so a long-lived unattended loop using background agents had a window where hard-block hooks were not actually enforced. Extends the v2.1.211/212/214 hook-decision-respect chain.

**CC v2.1.247+:** fixed a hook (or background agent) printing multi-megabyte error output from overflowing the conversation and stalling the session with "Prompt is too long." The same release also fixed unbounded memory growth when a hook/background task's output file couldn't be written — the location where output was lost is now recorded to a file. This repo runs several advisory hooks (`r007-r008-drift-advisor.sh`, `failure-ledger.sh`, `fail-axis-cause-advisor.sh`, etc.), so it is directly exposed to this failure class where hook output flooding could wedge the session itself — an extension of the v2.1.211/212/214/222 hook-reliability chain.

**CC v2.1.248+:** two hook-observability improvements: (a) a fix for `PermissionRequest`/`PreToolUse` hooks that emit invalid responses silently stalling a background session — `claude agents` rows now show the offending hook name and schema error. (b) a fix for hook stdout `{…}` objects that aren't valid JSON silently falling back to plain-text handling — these now surface as a parse error plus a hook error. Same lineage as the v2.1.214 "hook stdout JSON schema-validation failures don't reliably block per exit-code-2 docs" note above — hook failures continuing to move from silent to visible.

**Why advisory-first:**
1. Hard blocks can trap agents in unrecoverable states
2. Missing dependencies (jq, etc.) don't break the session
3. External skills and internal rules can coexist
4. Rules are re-injected after context compaction via the `SessionStart` hook (matcher `*`/`compact`), not the `PostCompact` event itself — see the correction under Overview

**Two-layer R007/R008 drift detection (as of #1229, extended #1545/#1553) — wiring, delivery, and firing all confirmed:**
- **Proactive** (#1229 + #1545 + #1553): `r007-r008-drift-advisor.sh` — wired to UserPromptSubmit (#1229, fires before each response), SubagentStop (#1545, closes the autonomous-loop gap for long-lived unattended loops like `/fsd` that re-enter via task notifications with no user input), and PostToolUse (#1553, covers the orchestrator-only stretch before the first subagent spawn) — the parser defect below silenced it through v1.1.42; fixed in v1.1.43.
- **Retroactive** (#1190): `session-reflection.sh` Stop hook — analyzes full transcript at session end — same `.role` vs `.message.role` defect, fixed alongside the proactive layer in v1.1.43.

**Delivery path implemented, then confirmed reachable (#1547 delivery mechanism + #1553 root-cause fix):** the SubagentStop wiring extension (#1545) closed the *trigger-point* gap, and #1547 (v1.1.40) correctly switched delivery from stderr (never model-visible on exit 0) to `hookSpecificOutput.additionalContext` on JSON stdout, deliberately omitting any top-level `decision`/`continue`/`stopReason` field so the hook stays non-blocking. Both fixes were real and correctly implemented — but a same-session measurement (2026-07-30) found the scripts never reached that delivery code path at all, because of the `.role`/`.message.role` parser defect described above. Wiring a hook to fire, and implementing its delivery mechanism correctly, are each necessary but neither is sufficient proof the advisory reaches the model — only a direct transcript/probe measurement is. **v1.1.43 fixed the parser and a live probe confirmed the first actual firing** (#1553).
