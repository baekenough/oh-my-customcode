# R021: Enforcement Policy

oh-my-customcode uses an advisory-first enforcement model. Most rules are enforced through prompt engineering rather than hard-blocking hooks, preserving agent flexibility while maintaining behavioral standards.

## Overview

Hard-blocking hooks are reserved for critical safety boundaries. The majority of MUST rules are enforced through PostToolUse advisory hooks, PostCompact re-injection, and CLAUDE.md prompt guidance. This prevents agents from getting trapped in unrecoverable states while still maintaining standards.

## Priority

**MUST** — The enforcement policy itself defines how all other rules are enforced.

## Key Requirements

**Enforcement tiers:**

| Tier | Mechanism | Rules | Behavior |
|------|-----------|-------|----------|
| Hard Block | PreToolUse hook, exit 2 | stage-blocker, dev-server tmux, rule-deletion-guard | Prevents tool execution |
| Soft Block | Stop hook prompt | [[r011]] session-end saves | Auto-performs then approves |
| Conversation Block | PostToolUse hook + `continueOnBlock` (CC v2.1.139+), exit 2 | stuck-detector, context-budget-advisor, cost-cap-advisor | Feeds rejection reason back into the conversation — Claude continues the turn aware of why the action was blocked |
| Advisory (proactive) | UserPromptSubmit + SubagentStop hooks | [[r007]], [[r008]] — `r007-r008-drift-advisor.sh` (#1229 UserPromptSubmit; #1545 added SubagentStop) | **Currently never fires** — see footnote below. |
| Advisory | PostToolUse hooks | [[r007]], [[r008]], [[r009]], [[r010]], [[r018]] | Warns via stderr, never blocks |
| Prompt-based | CLAUDE.md + rules/ + PostCompact | All MUST rules | Behavioral guidance in context |

**Advisory (proactive/retroactive) status correction (measured, 2026-07-30):** the `hookSpecificOutput.additionalContext` delivery path itself was correctly implemented in #1547 (v1.1.40) — but a **parser selector defect upstream of it** means the advisory has **never actually fired**. Both scripts read `jq -r '.role'`, but transcripts have no top-level `role` key (the real path is `.message.role`), so `last_assistant` is always empty and the script exits 0 silently before emitting anything. Measured: 0 occurrences of `"additionalContext":` across 771 transcripts, and a live probe emitted 0 bytes on both stdout and stderr. **Both the proactive layer (`r007-r008-drift-advisor.sh`) and the retroactive layer (`session-reflection.sh`, same defect) were silent.** Parser fix + `PostToolUse` wiring is in progress in v1.1.43 (Refs #1553). Lesson: **wiring confirmed ≠ delivery confirmed ≠ firing confirmed** — the [[r020]] "actual outcome ≠ attempt" principle reproduced in the hook domain.

**CC v2.1.163+:** Stop and SubagentStop hooks can return `hookSpecificOutput.additionalContext` (JSON) to feed structured feedback back into Claude's context without triggering a hook error label — enables advisory-style enforcement via Stop/SubagentStop hooks to pass richer context without disrupting turn continuation.

**CC v2.1.199+:** Fixed SessionStart/Setup/SubagentStart hooks silently swallowing stderr when exiting with code 2 — errors are now surfaced. Strengthens observability for the Hard Block/Advisory tiers in the table above (cf. the v2.1.163 `additionalContext` structured feedback note).

**CC v2.1.210+:** Fixed hook callback timeouts being misreported to the model as a user rejection, which had caused unattended sessions to stall waiting on a phantom denial. Since R021 advisory hooks fire every turn and long-running unattended loops (e.g. `/fsd`) depend on them, a hook timeout no longer aborts an unattended session.

**CC v2.1.211/212/214+:** Three platform fixes make hook enforcement decisions reliable in auto/unattended mode: (211) auto mode no longer overrides a PreToolUse hook's `ask` decision on unsandboxed Bash — the `ask` now floors to at least a minimal prompt; (212) `continue:false` hook halts are no longer dropped on tool failure or mid-completion, and hook infrastructure errors are no longer misreported as user rejections; (214) `exit 2` now reliably blocks even when hook stdout JSON fails schema validation. All three strengthen the Hard Block and Conversation Block tiers above (`stage-blocker`, `rule-deletion-guard`, `stuck-detector`), extending the v2.1.210 phantom-rejection fix.

**CC v2.1.222+:** fixed a PreToolUse auto-allow hook bypassing tool restrictions on background agent tasks (summaries/compaction/renames) — meaning the Hard Block tier above (`stage-blocker`, `dev-server tmux`, `rule-deletion-guard`) could previously be bypassed on that background-agent task path, so a long-lived unattended loop using background agents had a window where hard-block hooks were not actually enforced. Extends the v2.1.211/212/214 hook-decision-respect chain.

**Why advisory-first:**
1. Hard blocks can trap agents in unrecoverable states
2. Missing dependencies (jq, etc.) don't break the session
3. External skills and internal rules can coexist
4. PostCompact re-injection maintains rules after context compaction

**Hard-block promotion conditions:**

| Rule | Status |
|------|--------|
| [[r010]] | Candidate — orchestrator-direct-write violations > 3/session |
| [[r007]]/[[r008]] | Wiring implemented (#1229 UserPromptSubmit + #1545 SubagentStop, proactive; #1190 retroactive Stop-hook); `additionalContext` delivery path implemented (#1547, v1.1.40) but **never actually fires due to a parser selector defect** — see status correction above; fix in progress v1.1.43 (Refs #1553); hard-block variant still candidate if advisory insufficient (#1096) |

**Two-layer R007/R008 drift detection (as of #1229, extended #1545) — wiring complete, firing broken:**
- **Proactive** (#1229 + #1545): `r007-r008-drift-advisor.sh` — wired to UserPromptSubmit (#1229, fires before each response) and SubagentStop (#1545, closes the autonomous-loop gap for long-lived unattended loops like `/fsd` that re-enter via task notifications with no user input) — but see the parser defect above; it exits silently before ever emitting an advisory.
- **Retroactive** (#1190): `session-reflection.sh` Stop hook — analyzes full transcript at session end — same `.role` vs `.message.role` defect, also silent.

**Delivery path implemented but never reached (#1547 delivery mechanism + #1553 root-cause correction):** the SubagentStop wiring extension (#1545) closed the *trigger-point* gap, and #1547 (v1.1.40) correctly switched delivery from stderr (never model-visible on exit 0) to `hookSpecificOutput.additionalContext` on JSON stdout, deliberately omitting any top-level `decision`/`continue`/`stopReason` field so the hook stays non-blocking. Both fixes were real and correctly implemented — but a same-session measurement (2026-07-30, #1553) found the scripts never reach that delivery code path at all, because of the `.role`/`.message.role` parser defect described above. Wiring a hook to fire, and implementing its delivery mechanism correctly, are each necessary but neither is sufficient proof the advisory reaches the model — only a direct transcript/probe measurement is.

**Promoted to hard block:**
- `rule-deletion-guard.sh` (2026-04-08) — prevents accidental bulk deletion of rule files
