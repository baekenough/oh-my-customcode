# R002: Permission Rules

Defines tool permission tiers and file access boundaries for all agents.

## Overview

Tools are grouped into six tiers from always-allowed read-only tools to conditionally-available MCP tools. File access is scoped to the project. Agents must not attempt operations beyond their tier without explicit approval.

## Priority

**MUST** — Permission violations can cause unintended state changes or security breaches across the system.

## Key Requirements

**Tool tiers:**

| Tier | Tools | Policy |
|------|-------|--------|
| 1: Always | Read, Glob, Grep, ToolSearch | Free use, read-only |
| 2: Default | Write, Edit, NotebookEdit | State changes; notify before modifying important files |
| 3: Context | Agent, Skill, EnterPlanMode, ExitPlanMode, Monitor, TodoWrite, AskUserQuestion | Context-dependent, no user approval |
| 4: Approval | Bash, WebFetch, WebSearch | Request user approval on first use |
| 5: Conditional | Agent Teams tools (TeamCreate, SendMessage, etc.) | Available when Agent Teams enabled |
| 6: MCP | ListMcpResourcesTool, ReadMcpResourceTool, CronCreate, etc. | Available when MCP servers configured |

**File access:**

| Operation | Allowed | Prohibited |
|-----------|---------|-----------|
| Read | All source, configs, docs | — |
| Write | Source code, new files in project | `.env`, `.git/config`, paths outside project |
| Delete | Temp files created by agent | Existing files without request, entire directories |

**Permission request format:**
```
[Permission Request]
Action: {action} | Required: {tool} | Reason: {why} | Risk: Low/Medium/High
Approve?
```

**Deny rule glob patterns (v2.1.166+):** Deny rules in `settings.json` support glob patterns in the tool-name position — `"*"` denies all tools. Allow rules reject non-MCP globs. Unknown tool names in deny rules emit a startup warning.

**Per-parameter `Tool(param:value)` deny syntax (v2.1.178+):** Deny rules now support `Tool(param:value)` syntax to match a tool's input parameters, with `*` as a wildcard (e.g. `Agent(model:opus)` denies Opus subagent spawns). Extends v2.1.166 tool-name globs to per-parameter granularity. Complements `availableModels` ([[r006]]) for model-level access control and `mode: "bypassPermissions"` ([[r010]]) for subagent scope enforcement.

**Apple Events opt-in (v2.1.181+):** `sandbox.allowAppleEvents` setting added — opt-in to allow macOS Apple Events in the sandbox (default: off). Relevant when agents need to interact with GUI apps or AppleScript automation on macOS.

**Auth-stub MCP tools hidden in headless mode (v2.1.183+):** Tier-6 MCP auth-stub tools (those that exist solely to prompt the user to authenticate an MCP server) are no longer exposed to the model in headless/SDK (`-p`) mode. Previously, these stubs could surface in non-interactive runs and cause spurious tool-call attempts. No impact on interactive sessions.

**CLI MCP login + named-spawn deny enforcement (v2.1.186+):** Added `claude mcp login <name>` / `claude mcp logout <name>` to authenticate MCP servers from the CLI without the interactive `/mcp` menu (`--no-browser` stdin redirect for SSH). Also fixed `Agent(type)` deny rules and `Agent(x,y)` allowed-types restrictions not being enforced for named subagent spawns — extends the v2.1.178 `Tool(param:value)` per-parameter deny syntax to reliable enforcement on named spawns. Relevant to Tier-6 MCP and the Agent Tool Permission Mode.

**Org model restrictions on picker/env (v2.1.187+):** Org-configured model restrictions now apply to the model picker, `--model`, `/model`, and `ANTHROPIC_MODEL`, surfacing a "restricted by your organization's settings" message for a restricted model. Extends the v2.1.175 `enforceAvailableModels` managed-setting scope ([[r006]]) to the model picker/env entry points. Also added the `sandbox.credentials` setting (blocks sandboxed reads of credential files/secret env) — cross-ref [[r001]].

**Sandbox network memory + `/permissions` persist + MCP retry (v2.1.191+):** Sandbox network permission dialog now remembers hosts allowed with "Yes" for the rest of the session (no per-connection re-prompt). `/permissions` Recently-denied tab now persists an approved denial on close (previously discarded on close). Managed `forceRemoteSettingsRefresh` now takes effect via MDM/file policy with `Cache-Control: no-cache`. MCP capability discovery (`tools/list`/`prompts/list`/`resources/list`) and OAuth token requests now retry transient network errors with backoff (headless mode skips the browser popup). Relevant to Tier-4 (sandbox network) and Tier-6 (MCP) permission flows.

**`autoMode.classifyAllShell` + MCP auth auto-retry (v2.1.193+):** The `autoMode.classifyAllShell` setting sends ALL Bash/PowerShell commands (Tier-4) to the auto-mode classifier, not only arbitrary-code-execution patterns. Auto-mode denial reasons surface in the transcript, denial toast, and `/permissions` recent denials. When an MCP server needs authentication, CC shows a startup notification pointing to `/mcp`; MCP `headersHelper` auth auto-reruns and reconnects when a tool call returns 401/403 (Tier-6). Platform-level behavior coexisting with the tier-based policy above.

**External-plugin install consent on all loader paths (v2.1.195+):** External plugins enabled solely via a project `.claude/settings.json` now require explicit install consent on every loader path (previously some paths bypassed it). Strengthens the Tier-6 MCP/plugin trust boundary.

**Org default models + self-approved MCP block + `--dangerously-skip-permissions` fix (v2.1.196+):** Org default models were added — administrators set them in the org console, and `/model` shows "Org default" (or "Role default") when the user has not picked one, extending the v2.1.187 org model restriction scope to default-model resolution (cross-ref [[r006]]). Security: `claude mcp list`/`get` no longer spawns self-approved `.mcp.json` servers, and untrusted workspaces show `⏸ Pending approval` (Tier-6, cross-ref [[r001]]). Also fixed `claude agents --dangerously-skip-permissions` silently falling back to auto mode — it now shows a bypass notice and applies bypass mode to the spawned agent too (aligned with [[r010]] Universal bypassPermissions).

**`default` mode relabeled "Manual" + AskUserQuestion no longer auto-continues + MCP array-config crash fix (v2.1.200+):** The `default` permission mode is now displayed as "Manual" across CLI, `--help`, VS Code, and JetBrains — `--permission-mode manual` and `"defaultMode": "manual"` are accepted alongside the existing `default` value (label change only, same behavior; the `default` row in the tier table above remains valid, cross-ref [[r006]]). `AskUserQuestion` dialogs no longer auto-continue by default (previously they auto-advanced on idle) — idle-timeout auto-continue is now an explicit `/config` opt-in. This means autonomous/unattended flows (e.g. FSD) that call `AskUserQuestion` now block on user response instead of timing out — avoid the tool during unattended runs and proceed on best judgment (aligns with [[r015]] directive persistence). Also fixed a startup crash when `.claude.json`'s `disabledMcpServers`/`enabledMcpServers` held a non-array value (Tier-6 MCP).

**Manual-mode footer badge (v2.1.203+):** A gray ⏸ badge now shows in the footer while manual permission mode is active, keeping the active mode always visible — aligned with the v2.1.200 "Manual" relabel above.

**Auto mode on managed clouds + remote-settings consent fix (v2.1.207+):** Auto mode is now usable on Bedrock/Vertex/Foundry without the `CLAUDE_CODE_ENABLE_AUTO_MODE` opt-in (disable via the `disableAutoMode` setting). Also fixed `-p`/SDK non-interactive runs recording remote managed settings as consented without showing the consent dialog. Relevant to Tier-3/4 permission flows.

**Permission rule matcher caching (v2.1.208+):** Deny/ask permission rule matchers are now compiled once and cached, fixing multi-second per-turn slowdowns in sessions with many rules — a large deny/allow rule set no longer costs per-turn latency under the deny-by-default posture described above.

**`Write(path)`/`NotebookEdit(path)`/`Glob(path)` matcher warning (v2.1.210+, retired v1.1.45):** These forms are tool names, not path-scoped rule matchers, so writing a permission rule this way emits a startup warning — use `Edit(path)` for write rules and `Read(path)` for read rules instead. Extends the v2.1.166 unknown-tool-in-deny-rule warning to a more specific footgun. Retired to an HTML comment in the source at v1.1.45 under the [[r016]] version-note retention floor (visible notes kept at v2.1.212+); the guidance is unchanged, only its auto-injection cost was removed.

**Single-segment `dir/**` allow-rule scope narrowed (v2.1.214+):** An allow rule like `Edit(src/**)` previously auto-approved any nested `src/` anywhere in the tree; it now matches only `<cwd>/src`. Use `**/dir/**` if any-depth matching is intended. **Deny/ask rules keep any-depth matching** — only allow rules narrowed. Design settings.json scopes around this asymmetry (allow narrow, deny/ask broad).

**Bash permission-check bypass fixes (v2.1.221 → v2.1.223+):** v2.1.221 closed a hole where zsh could execute hidden commands inside `[[ ]]` regex conditionals without a permission prompt (this repo's Bash tool shell *is* zsh, so `[[ ... =~ ... ]]` forms containing commands are Tier-4 prompt candidates). v2.1.223 extended the same class of fix: a crafted command could **hide part of itself from the permission check** — meaning the string that was *checked* and the string that was *executed* could differ. The display-side counterpart of this (approval-dialog hiding) belongs to [[r001]].

**401 → OAuth token swap fix (v2.1.225+):** A transient 401 could cause CC to replace a long-lived `CLAUDE_CODE_OAUTH_TOKEN` with a stored short-lived token, breaking headless sessions until restart. On older CC, a cascade of auth failures following a single 401 in an unattended run is likely this swap bug rather than a token misconfiguration — distinguish the two when diagnosing.

**Agent-definition `bypassPermissions` vs org policy (v2.1.223+):** An agent definition's `bypassPermissions` mode previously ignored an org policy that disabled bypass permissions. [[r010]] "Universal bypassPermissions" is canonical for this.

## Agent Tool Permission Mode

Canonical source: [[r010]] "Universal bypassPermissions" owns the full requirement, rationale, and version history — always pass `mode: "bypassPermissions"` explicitly on every Agent tool call, since the Agent tool's default `mode` (`acceptEdits`) previously overrode agent frontmatter `permissionMode` and caused prompts during unattended execution.

**`mode` parameter deprecated, subagents inherit parent session mode (v2.1.212+):** CC now ignores the Agent (formerly Task) tool's `mode` parameter — subagents inherit the parent (orchestrator) session's permission mode by default. The per-call `mode: "bypassPermissions"` requirement above is now a no-op on v2.1.212+ (harmless to still pass it for CC < v2.1.212 compatibility). The actual gate for unattended bypass is now the **parent session's** permission mode, not the per-call flag — keep the orchestrator session on `bypassPermissions` to preserve unattended delegation.

## Enforcement

Prompt-based per [[r021]]. On insufficient permission: do not attempt, notify user, suggest alternative.
