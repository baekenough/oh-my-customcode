# R009: Parallel Execution Rules

Two or more independent tasks MUST execute in parallel. Sequential execution of parallelizable tasks is a violation.

## Overview

Parallel execution maximizes throughput and reduces wall-clock time. Before spawning 2+ parallel agents, the Agent Teams eligibility check ([[r018]]) must be performed — Agent Teams may be required instead of raw Agent tool calls. Adaptive splitting handles stalled agents at runtime.

## Priority

**MUST** — Enforced. Sequential execution of independent tasks requires correction. PostCompact hook re-injects this rule.

## Key Requirements

**Independence criteria (MUST parallelize):**
- No shared mutable state between tasks
- No sequential dependencies
- Each completes independently

**Agent Teams gate:** Quick rule — 3+ agents OR review cycle OR 2+ issues in same batch → use Agent Teams ([[r018]]).

**Execution limits:**

| Rule | Detail |
|------|--------|
| Max instances | 5 concurrent (soft default: 4) |
| Large tasks (>3 min) | MUST split into parallel sub-tasks |
| Orchestrator | Must stay singleton, never parallelized |

**Fable 5 long-lived subagent reuse (#1435):** Fable 5는 long-lived subagent 재사용(단일 subagent가 여러 단계를 이어서 수행)에 강함 — 현행 R009 병렬 실행 원칙과 상충하지 않으며, Fable 5 실행 시 short-lived 병렬 다수 대신 long-lived 재사용도 유효한 선택지. 상세는 `guides/claude-code/16-fable5-prompting.md`.

**Adaptive parallel splitting:** When an agent takes 2x+ longer than peers, spawn independent follow-up tasks immediately without canceling the stalled agent.

**Announce-execution consistency (Self-Check #6):** All tool calls announced in prose (e.g. "verify build + delegate fix 병렬") MUST be dispatched in the SAME message as the announcement — a tool that "runs next turn" instead is a violation. A specific sub-case, **verify-Bash + action-delegate asymmetry**, recurred twice (v1.1.22, v1.1.23): when a batch pairs a cheap verification Bash with an expensive action delegate (Agent/Workflow), the Bash fires but the delegate silently slips to the next turn. ≥2 occurrences triggered the [[r016]] rule-update mandate — both calls must be dispatched together.

**LLM Batch Output Token Budget:** The symmetric output-side counterpart to the input-side giant-prompt heuristic above. When one LLM call scores/classifies/extracts structured output (e.g. JSON) for N items, pre-compute `output_budget = N × per-item output tokens` BEFORE the call — exceeding `max_tokens` truncates mid-structure and causes a silent parse failure (the call "succeeds" but JSON.parse throws). Fix: chunk into ≤40-item batches and constrain per-item output length; raising `max_tokens` alone only defers the failure as the list grows (#1320, #1321).

**Display format:**
```
[1] mgr-creator:sonnet → Create Go agent
[2] lang-python-expert:sonnet → Review Python code
```

**Result aggregation:**
```
[Summary] {succeeded}/{total} tasks completed
  ✓ agent-1: success
  ✗ agent-2: failed (reason)
```

## Anti-Pattern: Single Agent Giant Prompt

단일 에이전트에 5000+ 토큰 multi-domain 프롬프트를 위임하는 것은 R009 위반이다. 이 패턴은 latency timeout, user cancellation, review loop 불가능을 유발한다.

**토큰 임계치 가이드 (#1085):**

| 조건 | 권장 |
|------|------|
| < 5000 tokens, single domain | 단일 에이전트 가능 |
| ≥ 5000 tokens 또는 3+ domains | 도메인별 분할 + 병렬 에이전트 (R009) |
| ≥ 8000 tokens 또는 4+ domains | Agent Teams 사용 필수 ([[r018]]) |

```
❌ WRONG: Single agent receives massive multi-domain prompt (>5000 tokens)
   Agent(arch-documenter, prompt: <9000-token M2 plan across 7 areas>)
✓ CORRECT: Pre-decompose by domain, spawn parallel agents per area
```

## Parallel Feature Integration Gate

Per-subagent "build green" does NOT guarantee integrated runtime correctness. When parallel feature subagents edit interdependent code (shared singletons, navigation stacks, API contracts), the orchestrator MUST run a combined build PLUS a runtime/smoke check (or device test for apps) after the parallel work merges — before declaring done.

> Origin: #1335 ③ — parallel lang-kotlin-expert rounds each reported "build green", but the combined runtime had a DataStore singleton crash, a Settings→Dashboard nav crash, a recording 400, and cursor pre-advance bugs — caught only by on-device testing.

| Anti-pattern | Required |
|--------------|----------|
| Trust each subagent's "build green" and declare done | Orchestrator runs a combined build + runtime/smoke gate on the merged result first |
