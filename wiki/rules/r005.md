# R005: Optimization Guide

Provides guidelines for efficiency, token optimization, and task batching — applied selectively where benefit is clear and measurable.

## Overview

Optimization should be applied to repetitive or bottlenecked operations. Strategies include parallelization, caching, lazy loading, and token compression. Readability always takes precedence — no optimization without measurable benefit.

## Priority

**MAY** — Optional. Apply when there is a clear, measurable gain. Never at the cost of readability or correctness.

## Key Requirements

**Efficiency strategies:**

| Strategy | When | Example |
|----------|------|---------|
| Parallel | 3+ independent I/O tasks | Read multiple files simultaneously |
| Caching | Same data accessed repeatedly | Cache file contents, reuse search results |
| Lazy Loading | Large datasets, partial use | Read only needed files, stream results |

**Tool-availability notes:**
- Do NOT assume a tool (e.g., `Glob`) is available without confirming on first exploration — prefer `Bash` (`find`/`grep`) when the available-tool set is unconfirmed (#1307).
- Tool names differ by platform — e.g., macOS lacks GNU `timeout` (use `gtimeout` from coreutils). Confirm platform-specific availability before use (#1327).
- **BSD sed `\?` 미지원 (#1413):** macOS BSD sed는 `\?`(optional 메타문자, GNU 확장)를 해석하지 않아 `sed 's|https\?://||'` 치환이 무음 실패한다. URL 도메인 추출 등은 `cut -d'/' -f3` 같은 POSIX 호환 수단을 사용한다.
- **Sandbox/container tool gaps (#1401):** `curl`, `wget`, `nc` 등 공통 CLI 도구는 샌드박스·컨테이너 환경에서 미설치일 수 있다. HTTP 요청에는 `WebFetch` 도구를 우선 사용하고, CLI 도구 사용 전 `command -v <tool>`로 가용성을 사전 확인한다.
- **로컬 실행 옵션 제시 전 자원 가용성 선확인 (#1455):** 로컬 실행에 의존하는 검증 옵션(로컬 스모크 테스트, 로컬 스크립트 실행 등)을 사용자에게 제시하기 **전에**, 그 실행에 필요한 로컬 자원(env 키, CLI 도구, 인증 상태)의 가용성을 먼저 확인한다. **저장소 secret 존재 ≠ 로컬 셸 env 존재** — `gh secret list`로 저장소 secret을 확인해도 로컬 셸에 해당 env가 있으리라 단정하지 말 것. 자원 부재 시 옵션에 전제조건을 명시하거나 제외하여 사용자가 실행 불가한 옵션을 선택했다 되돌리는 왕복(AskUserQuestion 재질문)을 방지한다. [[r020]](사전 검증)과 정합.
- **Shell output parsing — use Python, not read/grep (#1401):** adb bounds rect, 좌표쌍, JSON 분할 등 구조화된 출력 파싱은 `read`+`grep -o` 파이프라인 대신 `python3 -c "..."`를 사용한다. `read`+`grep -o` 조합은 공백 차이에 취약해 헛값을 산출한다. SSH 원격 `bash -c` 인자에 소괄호 포함 금지 — `ssh host "cmd; cmd2"` 형식 사용.
- **`ls | tail` 시계열 오판 (#1417):** `ls`는 파일명을 알파벳/사전순으로 정렬하므로 `ls <dir> | tail`로 "가장 최근 파일"을 판단하면 오판한다(파일명 순서 ≠ mtime 순서). 시계열 최신 판단은 `ls -t`, `find <dir> -newermt <ts>`, 또는 stat/timestamp 기반 정렬을 명시한다. `tail`만으로 "최신" 단정 금지.
- **`readdir` 순서는 플랫폼·런타임 의존이며 정렬되지 않는다 (#1599):** 디렉토리 열거 결과는 **정렬순도 생성순도 아니다** — bun의 `readdir`는 APFS에서 파일시스템 이름 해시 순서를 그대로 반환하고 node의 `readdirSync`와도 다른 순서를 낸다. "첫 항목"·"마지막 항목"으로 대상을 고르지 말고 정렬 키를 명시(`.sort()`, mtime 정렬)하거나 필터로 유일성을 보장한다. 열거 결과가 전부 디렉토리라고 가정하지 말고 `withFileTypes: true` + `isDirectory()`로 판별한다(관측 파일·`.DS_Store` 혼입). **테스트 파급:** 대상 디렉토리명이 `date -u +%Y-%m-%d`처럼 날짜에서 파생되면 이름이 바뀌는 날 해시 순서가 뒤집혀 **clean clone 첫 실행부터 달력 날짜의 절반에서 실패**한다(실측: 8/15 통과, 8/16~17 실패). 위 `ls | tail` 시계열 오판(#1417)의 **API 각도 변형** — 도구가 순서를 보장한다는 미확인 전제에서 결과를 해석한 같은 계열이다.
- **파이프 뒤 `$?`는 마지막 명령의 exit code (#1492, zsh 변형 #1540):** `script.sh | tail -N; echo $?`처럼 검증 스크립트를 파이프에 연결한 뒤 `$?`로 읽으면 파이프라인 **마지막 명령**(`tail`)의 종료코드를 얻는다 — 스크립트 자체가 실패해도 `tail`이 성공하면 `$?=0`으로 오판한다. **1차 지침은 파이프 없이 단독 실행.** 부득이 파이프를 쓸 때 원본 exit code를 읽는 문법은 셸마다 다르다 — bash `${PIPESTATUS[0]}`(대문자, 0-indexed) vs zsh `$pipestatus[1]`(소문자, 1-indexed), 서로 호환 안 됨. 이 저장소 기본 셸(및 Claude Code Bash 도구 실행 셸)은 **zsh**이므로 bash 문법을 그대로 쓰면 미정의 변수로 취급돼 **오류 없이 빈 값**을 반환 — 조건문에서 거짓으로 평가돼 "검증 통과"로 보이는 조용한 오판을 재생산한다. 셸을 사전 확인(`echo $SHELL`/`$BASH_VERSION`) 후 해당 문법을 쓴다. `${PIPESTATUS[0]}` 자체는 [[r023]] Workflow JS 템플릿 리터럴 이스케이프 이슈(#1438)와 별개 문제다. [[r020]] ("command executed" ≠ "succeeded")와 정합.
- **도구 이름 ≠ 그 프로그램 (#1590):** Bash 도구의 `grep`은 실제로는 셸 함수일 수 있다(이 저장소 실측: `ugrep --ignore-files` 위임 함수) — 그 함수가 `.gitignore`의 리터럴 `CLAUDE.md` 패턴을 따라 force-tracked 파일까지 재귀 탐색에서 **조용히(exit 0) 누락**시킨다. `type <tool>`로 실체(별칭/함수/바이너리)를 먼저 확인하고, 셸 함수 개입이 의심되면 `git check-ignore --no-index`로 진단한다. 저장소 전수 조사의 권위 소스는 [[r017]] Count Sync가 규정하는 `git grep`이다 — 셸 `grep`과 `git grep`의 계수 불일치는 STOP 신호이며 낮은 쪽을 채택하지 않는다.
- **계수/매칭 방법 확인 (#1521):** 카운트를 대조하기 전에 **비교 대상이 무엇을 어떻게 세는지** 먼저 확인한다 — 같은 지표라도 계수 방법이 다르면 값이 달라진다. 대표 함정 4종: (a) glob(`ls *.md`, 최상위만) vs 재귀 `find`(하위 디렉토리 포함), (b) 부분 문자열 grep(`grep "sdd"`가 `sdd-dev`까지 매칭), (c) 확장자 필터(`--include='*.md'`가 `CLAUDE.md.en`을 미매칭), (d) **머지 커밋 diff 기본 생략** — `git show --name-only <머지커밋>`은 diff를 기본적으로 출력하지 않아 변경 파일 0개로 오독된다. 머지 커밋의 변경 파일을 세려면 `--first-parent`(1차 부모 대비) 또는 `-m`(각 부모별 diff)을 명시한다. 검증 스크립트와 대조할 때는 **스크립트의 실제 계수 로직을 읽고** 같은 방법으로 센다. 위 `ls | tail` 시계열 오판(#1417)과 동류로, 도구의 기본 동작을 확인하지 않은 채 결과를 해석해 오탐에 이르는 패턴이다. Origin: #1521 (2026-07-20 세션에서 3회 반복; 두 서브에이전트가 독립적으로 동일 오탐에 도달); (d)는 #1553 찐빠 #4 (2026-07-30 세션에서 머지 커밋 `--name-only` 0파일을 "변경 없음"으로 오독).

**Capability-aware tool scheduling:**

Per-tool capability awareness extends [[r009]] parallel-execution detection to tool-level scheduling:

| Capability | Parallelizable? | Example |
|-----------|----------------|---------|
| Read-only, no side effects | Yes | Read, Glob, Grep |
| Write with independent targets | Yes | Write(file-A) + Write(file-B) |
| Write with shared target | No | Sequential edits to same file |
| External with rate limits | Throttle | WebFetch, API calls |

Inspired by [ouroboros PR #353](https://github.com/Q00/ouroboros/pull/353) capability graph pattern.

**Platform tool-reliability notes:**
- **v2.1.208+ — RETIRED in v1.1.44:** the tool-reliability fix list (scientific-notation env vars, Edit-after-modification, empty-file Read, Grep/Glob edge cases) was HTML-comment retired in the source rule because v2.1.208 falls below the [[r016]] v2.1.212 version-note retention baseline. Behavior unchanged; text still Read-tool-visible in `.claude/rules/MAY-optimization.md`.
- **v2.1.210+ (retired v1.1.45):** Auto-backgrounded Bash/PowerShell commands no longer apply `cd` — cwd-dependent follow-ups after auto-background need absolute paths. Grep pagination past the result end returns "No matches found" (page end, not absence). Retired to an HTML comment in the source under the [[r016]] v2.1.212 retention baseline; the advice still holds, only its auto-injection cost was removed.
- **v2.1.212+:** Slow MCP tool calls (>2min default, tunable via `CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS`) auto-background — do not treat a slow ontology-rag/code-review-graph call as hung.
- **v2.1.224+:** MCP tools connected mid-turn were deferred to tool search **without their names being announced**, so a session-attached MCP server's tools could be invisible and misread as "no such tool". Apply the same discipline as the `command -v` pre-check above to MCP tools: confirm absence with `ToolSearch` before concluding a tool does not exist.
- **v2.1.228+ — Write no longer enforces read-before-write on newer models:** Write may now overwrite an existing file that was not read this session (matching Edit's rule); older models still require the prior read. Two consequences: "the Write failed, so the file wasn't read" is no longer a universally valid diagnosis, and **writing an unread file silently destroys its previous contents**. Keep "use Edit for partial changes, Write only for full replacement" as a *procedure* now that the tool no longer enforces it. Also fixed: the deferred-tools reminder was delivered to the model twice after a skill invocation (duplicate context spend).
- **v2.1.233+ — `WebFetch` cache TTL is now tunable (`CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS`, default still 15 min):** The re-verification trap this creates matters more than the setting itself — **re-fetching the same URL within the TTL returns the cache, so it is not an independent second look.** Never use a repeat `WebFetch` of the same URL as the "deterministic second source" that [[r020]]'s Degraded-Output Re-Verification Gate demands; use a different source or a CLI measurement (`npm view`, `gh`) instead.
- **v2.1.229+ — non-string tool arguments crashed the session:** A non-string `glob`, `file_path`, or `command` value crashed to an error screen, and the crash **recurred on `--resume` of that session** while leaving no hint that the argument *type* was the cause. When assembling tool arguments programmatically, guarantee string types (cross-ref [[r023]] Workflow Script Sanity Check). A narrow-terminal `RangeError` crash while rendering progress bars/markdown tables (also on `claude --continue`/`--resume` startup) was fixed in the same release.

- **v2.1.233+ — Linux Bash memory cgroup + idle-CPU fix (both Linux-only, currently N/A here):** Bash tool commands can be placed under a **memory cgroup** on Linux via the opt-in `CLAUDE_CODE_TOOL_MEMORY_LIMIT`, so a runaway build can no longer freeze the session. Where that variable is set, a large build/test may now be **OOM-killed** — check for it before characterizing the failure as a code defect ([[r020]] Read-Before-Characterize). The same release fixed **idle sessions pegging one CPU core at 100% on sandbox-enabled Linux**; on older Linux, CPU-saturation/timeout failures in parallel batches had to rule out that constant idle draw before being attributed to load (cross-ref [[r009]] 「파일 disjoint ≠ 자원 disjoint」). This repo runs on Darwin, so both items apply only to Linux CI/containers.

**Token optimization:**
- Include only necessary info, remove duplicates, use summaries
- Concise expressions, minimize code blocks, no unnecessary repetition

**Task optimization:**
- **Batch**: Group similar tasks (edit 10 files at once)
- **Incremental**: Process only changed parts

**When to optimize:**

| Do | Don't |
|----|-------|
| Repetitive tasks, clear bottleneck, measurable gain | One-time tasks, already fast, complexity > benefit |

**Context optimization via HTML comments (v2.1.72+):** Move model-unnecessary metadata into HTML comments in `.md` files to reduce context token usage.

## Enforcement

**MAY** — No enforcement mechanism. Applied at agent discretion.
