# R019: Routing Enrichment Rules (Wiki-RAG)

Routing skills SHOULD use Wiki-RAG enrichment to improve agent/skill/guide selection accuracy. Enrichment is advisory only. (The source file keeps its historical name `SHOULD-ontology-rag-routing.md`; the rule title is "Routing Enrichment Rules".)

## Overview

When static routing confidence is below 90%, the routing skill queries `wiki/index.yaml` for relevant agent/skill/guide pages and injects the findings as supplementary routing signals. It never replaces static routing, and a lookup failure must never block or delay routing. Since v2.0.24 (#1960) Wiki-RAG is the only enrichment layer: the former ontology-RAG layer (MCP server, `get_agent_for_task`, `.claude/ontology` data) was removed completely.

## Priority

**SHOULD** — Strong recommendation. Enrichment improves agent effectiveness but is advisory-only.

## Key Requirements

**Integration pattern:**
```
Static routing → ambiguous (confidence < 90%)
  ↓
wiki/index.yaml search for matching pages
  ↓
Extract agent/skill/guide suggestions
  ↓
Inject as suggested_context in agent prompt
```

**Failure handling:**

| Scenario | Action |
|----------|--------|
| wiki/index.yaml missing | Skip silently, proceed without wiki enrichment |
| Returns empty | Proceed with unmodified prompt |
| Parsing error | Skip silently, log warning |

**Enrichment failure MUST NOT block or delay routing.**

**Scope:** Applies to all four routing skills: secretary-routing, dev-lead-routing, de-lead-routing, qa-lead-routing (each has a "Wiki-RAG Enrichment (R019)" step).

## Enforcement

Prompt-based per [[r021]]. Advisory only.

## Relationships

- **Related rules**: [[r010]] (the routing skill reads `wiki/index.yaml` read-only; the spawned subagent receives the enriched prompt), [[r015]] (confidence thresholds and display unchanged), [[r009]] (lookup adds `suggested_context` to the prompt; no parallelism impact), [[r022]] (Wiki-RAG quality depends on an up-to-date wiki)
- **Affects**: All routing skills and spawned specialist agents
